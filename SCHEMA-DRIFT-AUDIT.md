### Why `invoices.amount` is the most urgent frontend fix
Dashboard.tsx line 135 uses `Promise.all` across 7 queries. A 400 on any one rejects the batch.
The `invoices` query asks for `amount` but the schema column is `total` → 400 → entire dashboard
data load fails → catch sets `setStats(null)` → dashboard renders with blank widgets.
Either rename the select to `total` (recommended, matches schema) or add `amount` as a column.

## 3. Realtime publication gap (the `postgres_changes` error) — config, not a code bug

The frontend correctly uses `.channel().on().subscribe()` ordering at ALL call sites (verified:
useRealtime.ts, NotificationBell, Notifications, NotificationsCenter, Chat, LiveChat, FreshnessBadge).
The `postgres_changes` error is because only 3 tables are in the `supabase_realtime` publication:

```sql
-- 999_fix_missing_tables.sql:386-388 — only these are published
ALTER PUBLICATION supabase_realtime ADD TABLE channels;
ALTER PUBLICATION supabase_realtime ADD TABLE messages;
ALTER PUBLICATION supabase_realtime ADD TABLE tasks;
```

But the frontend subscribes to realtime on these UNpublished tables:
- `notifications` (NotificationBell, Notifications, NotificationsCenter)
- `business_events` (FreshnessBadge)
- `chat_messages` (LiveChat)

Fix: `ALTER PUBLICATION supabase_realtime ADD TABLE notifications, business_events, chat_messages;`
(server-side). Not a `.on()`-after-`.subscribe()` bug.
